# LUMI Employee Data Ingestion Platform

An end-to-end employee data ingestion pipeline built with Spring Boot, Apache Airflow, Apache Beam, PySpark, MySQL, and PostgreSQL.

The Spring Boot gateway accepts an ingestion request and starts an Airflow DAG. Airflow validates the input, runs the shaded Apache Beam pipeline, and verifies that the number of records written to MySQL matches the control-file count generated by the gateway.


## Repository layout

| Directory | Purpose |
| --- | --- |
| `SpringBoot_Gateway/ingestion` | REST API, request validation, control-file creation, file-format detection, Airflow triggering, and PySpark orchestration. |
| `AirFlow_WorkFlow` | Docker Compose deployment for Airflow and PostgreSQL, the `pipeline-trigger` DAG, mounted data, JAR, logs, and error output. |
| `ApacheBeam_Job/beam-ingestion-pipeline` | Maven Java 17 project containing parsing, validation, cleansing, encoding, database writing, and error logging. |
| `PySpark_Splitter` | Local PySpark utility that splits large inputs into ordered part files. |

The `data`, `logs`, `errors`, `split_*`, `target`, and `jar` contents are runtime or build artifacts. The checked-in sample files can be used for local testing, but new generated output should not be committed.

## Processing flow

1. A client sends an input file path to `POST /api/ingestions`.
2. The gateway creates an execution UUID and detects `csv`, `json`, or `txt` input.
3. The gateway counts source records and writes a control file containing `record.count` and `recordCount`.
4. Files larger than the configured 1 MiB threshold are split by `PySpark_Splitter/splitter_final.py`. JSON files below the threshold are flattened to one JSON value per line.
5. The gateway triggers the Airflow `pipeline-trigger` DAG with the input path, extension, execution ID, error-log path, and control-file path.
6. Airflow validates the input and runs `beam-ingestion-pipeline.jar` with Apache Beam's `DirectRunner`.
7. Beam parses records, sends malformed or invalid records to an error output, cleanses null values, Base64-encodes phone and salary values, and inserts valid records into MySQL.
8. Airflow reads the expected count from the control file and checks `COUNT(*)` in `employee_warehouse` for the current execution ID.

## Prerequisites

- Windows with Docker Desktop and Docker Compose
- Java 17
- Maven 3.8+ (or use the Spring Boot Maven wrapper for the gateway)
- Python 3.9+ and PySpark for large-file splitting
- A running MySQL instance reachable from the Beam process
- A MySQL database named `beam_warehouse` with an `employee_warehouse` table matching the insert columns in `DatabaseWriter.java`

The Airflow container uses Airflow 2.9.3 and installs a Java 17 JRE. PostgreSQL is used only for Airflow metadata; employee records are written to MySQL.

## Configuration

Create `AirFlow_WorkFlow/.env` locally. Do not commit it. A minimal shape is:

```dotenv
INGESTION_DB_USERNAME=<mysql-user>
INGESTION_DB_PASSWORD=<mysql-password>
INGESTION_DB_URL=jdbc:mysql://host.docker.internal:3306/beam_warehouse

POSTGRES_USER=airflow
POSTGRES_PASSWORD=<postgres-password>
POSTGRES_DB=airflow

AIRFLOW_SECRET_KEY=<long-random-value>
AIRFLOW_ADMIN_USERNAME=airflow
AIRFLOW_ADMIN_PASSWORD=<airflow-password>
AIRFLOW_ADMIN_FIRSTNAME=admin
AIRFLOW_ADMIN_LASTNAME=user
AIRFLOW_ADMIN_EMAIL=admin@example.com
```

The gateway reads these properties from `SpringBoot_Gateway/ingestion/src/main/resources/application.properties`:

| Property | Default / purpose |
| --- | --- |
| `AIRFLOW_API_URL` | `http://localhost:8082` |
| `AIRFLOW_DAG_ID` | `pipeline-trigger` |
| `AIRFLOW_DEFAULT_ERROR_LOG_PATH` | `/opt/airflow/errors` |
| `ingestion.file.size.threshold` | `1048576` bytes |
| `pyspark.script.path` | Absolute path to `splitter_final.py`; update this for your machine. |

The gateway and Airflow must agree on mounted paths. The gateway translates a host path containing `airflow_505` to `/opt/airflow` before sending the DAG request, because `airflow_505` is mounted at `/opt/airflow` inside the containers.

## Build and start

### 1. Build the Beam pipeline

```powershell
cd ApacheBeam_Job\beam-ingestion-pipeline
mvn clean package
Copy-Item target\beam-ingestion-pipeline-1.0-SNAPSHOT.jar ..\..\AirFlow_WorkFlow\airflow_505\jar\beam-ingestion-pipeline.jar -Force
```

The Maven shade plugin creates the executable JAR with `com.amex.lumi.Ingestion` as its main class.

### 2. Start Airflow and PostgreSQL

```powershell
cd AirFlow_WorkFlow
docker compose up --build -d
```

Airflow is available at <http://localhost:8082>. Use the administrator credentials from `.env`.

To inspect service output:

```powershell
docker compose logs -f airflow-scheduler
docker compose logs -f airflow-webserver
```

### 3. Start the gateway

Update `pyspark.script.path` for the local checkout, then run:

```powershell
cd SpringBoot_Gateway\ingestion
.\mvnw.cmd spring-boot:run
```

The gateway listens on Spring Boot's default port, `8080`.

## Trigger an ingestion

The gateway endpoint is:

```http
POST http://localhost:8080/api/ingestions
Content-Type: application/json
```

Example request using a sample JSON file:

```json
{
  "inputFile": "C:/path/to/Capstone_AMEX_LUMI/AirFlow_WorkFlow/airflow_505/data/employee_data.json",
  "errorLogPath": "C:/path/to/Capstone_AMEX_LUMI/AirFlow_WorkFlow/airflow_505/errors/employee-errors",
  "controlFile": "C:/path/to/Capstone_AMEX_LUMI/AirFlow_WorkFlow/airflow_505/controlFile.txt"
}
```

Example response:

```json
{
  "executionId": "<execution-uuid>",
  "dagId": "pipeline-trigger",
  "dagRunId": "ingestion-<execution-uuid>",
  "status": "TRIGGERED"
}
```

`inputFile` may point to a single file or a directory. Supported input extensions are `.json`, `.csv`, `.txt`, and `.dat`. For a directory, Beam recursively selects files with the detected extension and processes them in sorted order.

## Beam command-line options

The executable JAR accepts the following options:

```text
--inputPath       File, directory, or input path
--fileExtension   json, csv, txt, or dat
--executionId     UUID attached to every inserted record
--errorLogPath    Output prefix for parse and validation errors
--controlFile     Optional control file containing record.count or recordCount
```

To run Beam directly, make sure the MySQL environment variables are available:

```powershell
$env:INGESTION_DB_URL = "jdbc:mysql://localhost:3306/beam_warehouse"
$env:INGESTION_DB_USERNAME = "<mysql-user>"
$env:INGESTION_DB_PASSWORD = "<mysql-password>"
java -jar AirFlow_WorkFlow\airflow_505\jar\beam-ingestion-pipeline.jar `
  --inputPath="ApacheBeam_Job\beam-ingestion-pipeline\employee_data.csv" `
  --fileExtension="csv" `
  --executionId="00000000-0000-0000-0000-000000000001" `
  --errorLogPath="AirFlow_WorkFlow\airflow_505\errors\beam-errors"
```

## PySpark splitter

The splitter is normally called by the gateway for files above the size threshold. It can also be run directly:

```powershell
python PySpark_Splitter\splitter_final.py `
  --input_path "C:\data\employee_data.csv" `
  --output_path "C:\data\split-output" `
  --file_format csv `
  --max_records 5000
```

The output directory contains ordered `part-00000.*` files and a `_SUCCESS` marker. The splitter refuses to process an empty input or overwrite an existing output directory.

## Data handling and validation

- CSV input expects the employee header and employee fields shown in `ApacheBeam_Job/beam-ingestion-pipeline/employee_data.csv`.
- JSON input accepts either one employee object per line or a JSON array. Nested `address` and `emergency_contact` objects are mapped to the warehouse fields.
- TXT and DAT input use the fixed-width parser.
- Invalid parse and validation records are written to a single-shard `.txt` error file.
- Validation checks identifiers, field lengths, dates, phone numbers, currency, employment status, boolean status, salary, address, and emergency contact fields.
- Null values are normalized before insertion. Phone numbers and salaries are Base64-encoded in the transformed record; the database writer inserts the encoded phone value and the original salary value.

## Testing and troubleshooting

Build and run the Beam tests:

```powershell
cd ApacheBeam_Job\beam-ingestion-pipeline
mvn test
```

Build and run the gateway tests:

```powershell
cd SpringBoot_Gateway\ingestion
.\mvnw.cmd test
```

Common checks:

- `No .<extension> files found`: verify the path is visible to the Airflow container and the extension matches the request.
- `INGESTION_DB_URL is missing`: verify `AirFlow_WorkFlow/.env` and recreate the Compose services.
- Record-count mismatch: compare the generated control file, Beam error log, and `employee_warehouse` rows for the returned `executionId`.
- PySpark failures on Windows: verify Python, PySpark, Java, and Hadoop `winutils.exe`/`HADOOP_HOME` availability.
- Airflow DAG not visible: check the scheduler logs and confirm `airflow_505/dags/pipeline-trigger.py` is mounted.

## Security notes

- Keep `.env`, database passwords, and Airflow credentials out of Git.
- Replace the development credentials in `application.properties` with environment-backed configuration before deployment.
- The current encoding step is Base64, which is reversible encoding rather than encryption. Use a managed encryption solution for production-sensitive fields.
- Restrict the gateway and Airflow API to trusted networks and add authentication, authorization, and TLS at the deployment boundary.
